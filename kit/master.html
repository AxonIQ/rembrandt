Cards · Master Slide Deck · #07

Event-sourced systems are outgrowing generic databases

Three properties a relational store cannot give you, however well you tune it.

Active push delivery

Events reach every consumer the moment they commit. No polling overhead, no batch lag, no missed updates between systems.

Failure isolation

Context-aware clustering gives each business domain its own boundary. Trouble in one context never cascades into the next.

A flat performance curve

Append-only segment files keep writes fast at any history size. Performance does not degrade as you grow.

Fixed aggregates versus dynamic boundaries

DimensionFixed aggregatesDynamic consistency boundaries
Boundary definitionDefined by structure. Every event belongs to at most one aggregate.Expressed through tags. One stored event takes part in every boundary its tags allow.
Consistency scopeFixed per schema, decided when the model is designed.Formed per operation, at the moment the operation runs.
Cross-entity rulesCoordinated through processes and sagas.Atomic across domain concepts, without processes and sagas.
Changing the modelA data migration, with history rewritten to fit.Boundaries move by changing tag queries. History stays put.

Tables · Master Slide Deck · #22

Shared language for the rest of this deck

Event sourcing
Persist every change as an immutable event instead of overwriting state. Current state is derived by replaying history, so the record is complete by construction and any past state can be reconstructed on demand.
CQRS
Command Query Responsibility Segregation. Writes go through commands that append events, reads come from projections built for each question. Both sides scale and evolve independently.
Dynamic consistency boundary
An architectural model that defines the scope of transactional consistency per operation, at the moment it runs, rather than binding it to a fixed aggregate. Introduced by Sara Pellegrini and Milan Savic in 2024.
Projection
A read model folded from the event stream. Cheap to build, cheap to throw away, and rebuildable from history at any time, which makes schema changes reversible.
